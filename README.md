# A 股趋势筛选工作台 · 纯前端版

移动端优先的 A 股趋势筛选工作台。四层漏斗筛选 + 个股七步分析 + 学习模式，
**纯静态站，零服务器、零备案**，直接部署到 GitHub Pages。

本项目是 `TushareWorkbench`（Swift + React 双端）的网页版重构：保留全部分析能力，
把数据源换成实时可用的公开行情接口，并把引擎抽成可复用独立包。

## 使用指南

面向使用者（同学）的完整说明：**[docs/user-guide.md](docs/user-guide.md)**

站内也有同一份内容 —— 页头右上角**「使用说明」**按钮。给同学的链接只需发站点地址，
不用另外发文档。

## 与旧版的关系

| | 旧版 | 本项目 |
|---|---|---|
| 形态 | iOS App + 网页原型 | 纯网页（移动端优先） |
| 分析引擎 | TS 与 Swift **两套实现**，靠 fixture 测试防漂移 | **一套**（`@aw/core`） |
| 数据源 | akshare 申万 + 腾讯 + **Tushare 市值** | akshare 申万 + 腾讯 + **东方财富市值**（已去除 tushare） |
| 实时性 | 每日快照 | 每日快照 **+ 秒级实时** |
| 部署 | GitHub Pages / Xcode | GitHub Pages |
| 后端 | 无 | 无（数据源支持 CORS 直连） |

## 架构

```
同花顺/东财/腾讯公开行情（浏览器直连）
        ↑
   ┌────┴─────────────────────────────┐
   │  每日快照（GitHub Actions 生成）    │  ← 批量历史：指数/板块/500+ 个股
   │  data/snapshot_<YYYYMMDD>/       │
   └────┬─────────────────────────────┘
        ↓
packages/core   分析引擎（纯函数、零依赖、不碰时间与时区）
packages/data   快照加载 + 多源实时行情（降级链）+ 交易时段判断
apps/web        React 界面
```

**为什么是「快照 + 实时」两层**：四层漏斗需要 500+ 只股票的 K 线，浏览器逐票拉取会被
行情站限频乃至封 IP（实测东财会直接把连接重置）。所以批量历史放服务端每天生成一次，
浏览器只实时刷当前关注的一小部分标的。详见 `docs/data-sources.md`。

## 部署到 GitHub Pages

1. 新建公开仓库并推送；
2. `Settings → Pages → Source` 选 **GitHub Actions**；
3. push 到 `main` 会自动构建部署，地址形如 `https://<用户名>.github.io/<仓库名>/`。

仓库内已含两个工作流：

- `.github/workflows/update-snapshot.yml` — 每工作日 18:30（北京时间）抓当日快照并提交
- `.github/workflows/deploy-web.yml` — 跑测试 → 同步快照 → 构建 → 部署

**源码里没有任何密钥。** 本版所有数据源都是免密钥的公开接口，不需要配置任何 Secret。

## 模拟投资游戏

第五个标签页「模拟盘」：虚拟账户 + 真实行情撮合 + 赛季结算。

**撮合规则贴合 A 股实际**，因为这些规则本身就是学习内容：

| 规则 | 处理 |
|---|---|
| T+1 | 当日买入当日不可卖 |
| 涨跌停 | 涨停不可买、跌停不可卖（主板 ±10%、创业板/科创板 ±20%、ST ±5%） |
| 费用 | 佣金万 2.5（最低 5 元）、印花税千 1（仅卖出）、过户费万 0.1（双向） |
| 滑点 | 默认 0.1%，模拟冲击成本 |
| 一手 | 100 股；卖出可不足一手但须一次性清仓 |
| 停牌/无行情 | 拒绝下单，**不猜价格** |
| 非交易时段 | 允许下单但按最近收盘价成交，并在成交记录中标注 |

**结算必须对标基准**（沪深300）——只看绝对收益的话，牛市里人人都是股神。
成绩以**超额收益**表达，并给出最大回撤、胜率、成交笔数。

### 模拟盘与分析红线的关系（重要）

项目红线禁止界面出现「买入/卖出/目标价」。模拟盘必然要有买卖按钮，
两者不冲突的关键是分清**谁在决策**：

- 分析引擎给结论 → **程序在建议** → 红线禁止
- 玩家自己下单 → **用户在选择** → 模拟盘的职责只是撮合与记账

因此模拟盘被允许出现买卖标签，但受更严格的替代约束（有测试守护）：
常驻免责声明、不出现任何引导性文案、引擎分类只作客观依据展示。
红线源码扫描的唯一豁免文件名**写死在测试里**，不能被悄悄扩大。

## 交易信号

`packages/core/src/signal.ts` 把引擎的分类结果派生为可执行的买卖信号：

| 引擎分类 | 信号动作 |
|---|---|
| 启动观察 | **买入** |
| 回调观察 | **买入** |
| 趋势观察 | 增持 |
| 高位观察 | 减持 |
| 排除 | 卖出 |
| 数据不足 | 观望 |

每只股票给出：**动作**、**强度（0-100）**、一句话结论，以及三个参考价位——
参考买入价（20 日线）、参考止损价（-2×ATR）、参考目标价（+3×ATR），另附 20 日压力位与风险报酬比。

信号是**叠加在引擎之上的派生层，刻意不改动 `engine.ts`**：那边是自旧项目逐字节搬移、
由 12 个 fixture 守护的行为基线。这样调整信号规则永远不会影响引擎的一致性测试。

### 关于原「产品红线」

本项目早期把四条列为硬红线：不出现买卖信号、每个结论带依据、数据不足不编造、不预测走势。
其中**第一条（不出现买卖信号）已按项目所有者决定移除**——因为向他人提供买卖建议在境内
需要证券投资咨询资质，这是一个合规取舍而非技术问题，现由所有者承担该判断。

**其余三条保留**，但它们的性质不同：不是限制，而是保证结论可核对的前提。
`NOT_ENOUGH_BANNER`、逐条判断依据、ATR 测算而非承诺，都是这个意义上的设计。

## 回放压测：信号质量（结论：**无可测量的边缘**）

`scripts/backtest.ts` 做逐日 walk-forward 回放：对每个历史交易日 D，**只用 [0, D] 的数据**
跑一遍完整链路（四层漏斗 + 信号），再看 D 之后 5/10/20 日的实际走势。

```bash
# 默认快照只有 120 天，回测样本不足。先拉长历史：
python3 packages/data/scripts/fetch_snapshot.py --days 650
npx vite-node scripts/backtest.ts
```

> **本节的结论经过四轮修正**，保留过程是因为它本身就是一份教材：
> 同一个数据集，方法不同，结论从"信号是反的"一路退到"什么都没证明"，
> 最后在样本扩大 10 倍后才得到确定答案。

### 健壮性 ✅

640 日快照、580 个可回放交易日、53360 个信号样本：**0 异常、0 空信号日、强度无越界**。
引擎在各种市场状态下都稳定产出。

### 漏斗行为正确 ✅

信号分布随市场状态显著变化，这正是漏斗的设计意图：

| 大盘状态 | 天数 | 买入 | 增持 | 减持 | 卖出 |
|---|---|---|---|---|---|
| 强 | 113 | 15% | 45% | 10% | 30% |
| 正常 | 306 | 9% | 31% | 3% | 57% |
| 偏弱 | 161 | 6% | 20% | 1% | 73% |

### 信号质量 ❌ 无有效区分度

回放区间沪深300 **+23.21%**（2024-02 ~ 2026-09，牛市）。三个检验一致指向零效应：

| 检验 | +5日 | +10日 | +20日 |
|---|---|---|---|
| 看多 − 看空 价差 | +0.19pp | +0.16pp | +0.27pp |
| **分块自助法 95% 区间** | [−0.17, +0.57] | [−0.57, +0.87] | [−0.95, +1.34] |
| **稀疏非重叠均值** | **−0.01pp** | **+0.32pp** | **+0.03pp** |
| 独立起点数 / 为负比例 | 115 / 46% | 57 / 40% | 28 / 43% |
| 逐日检验（重叠校正后 t） | −0.01 | −0.05 | +0.08 |

**三个窗口的置信区间全部跨越 0，非重叠均值在 −0.01 ~ +0.32pp 之间，为负比例接近抛硬币。**
结论：**效应量与噪声无法区分** —— 这个信号既不反向、也不有效，就是没有信息量。

> 重要：**方向是对的**（看多略优于看空），只是幅度小到没有意义。
> 早期 60 天样本得出的"方向相反"是小样本假象 —— 若据此反手做，
> 等于把噪声当信号，而且方向还是错的。

### 四轮修正的过程（为什么值得保留）

| 轮次 | 样本 | 方法 | 结论 |
|---|---|---|---|
| 1 | 60 天 | 看均值 | "信号是反的" ❌ 过度断言 |
| 2 | 60 天 | + 分块自助法 / `t/√h` | "存疑" |
| 3 | 60 天 | + 稀疏非重叠（仅 2~11 起点） | "证据不足" |
| 4 | **580 天** | 同上，起点增至 28~115 个 | **"无有效区分度"** ✅ |

每一轮都在收紧。第 3 轮时我说"证据不足"，那不是谦辞 —— 2 个独立起点确实什么都说明不了。
**唯一的出路是扩大样本**，而这一步靠把 `--days` 从 130 提到 650 就完成了。

### 数据质量

| 项 | 数值 | 说明 |
|---|---|---|
| 收盘价 null 占比 | 0.1189%（70/58880） | 9/92 只个股存在停牌缺失 |
| 缺失删样率 | 0.21% ~ 0.26% | 非随机删样的潜在影响很小 |
| 边界截断 | 0.9% ~ 3.4% | 起点靠近末尾导致，属数据不足非偏差 |

### 仍然存在、且**无法在当前数据下修复**的偏差

**股票池前视 / 生存偏差**：回放每天都遍历固定的 `full.stocks`，而池子是按**当前**
市值权重选出的代表股。要做对需要每个历史时点的成分股与市值快照。

**因此结论只适用于"这个固定且可能前视的股票池"，不能外推。**

### 结论与建议

1. **不要把信号当交易依据**。界面已显示 `SIGNAL_BACKTEST_CAVEAT` 如实告知；
2. **不要反手**。方向本来就是对的，只是没有幅度 —— 反手是把噪声当信号；
3. 引擎与漏斗本身是好的（健壮性、状态分布都正确），**问题在"分类→收益"这一跳**，
   即当前的分类阈值与收益没有稳定映射；
4. 若要继续，方向是**找出有预测力的因子**（而非调整现有阈值），
   并用同一套回测验证 —— 现在这套工具已经就绪，改一行就能重测。

## 已知限制

- **东方财富会封锁高频请求的 IP**（实测），因此默认链是腾讯优先、东财兜底；降级发生时界面会标注实际来源。
- 腾讯实时接口**单次最多 20 只**，且为 **GBK 编码**（已处理）。
- 腾讯 K 线**不支持批量**，一次一只；指数返回键是 `day` 而非 `qfqday`。
- 申万一级行业依赖 akshare，上游改版可能导致快照生成失败（已有降级与告警）。
- 交易日历来自快照的 `calendar.json`，快照未更新时节假日判断会退化为「仅按周末粗判」。

## 开发提示

> ⚠️ **不要把本项目放在 `~/Documents` 或 `~/Desktop`。** 这两个目录默认开启 iCloud
> 「桌面与文稿」同步；磁盘吃紧时 macOS 会把文件卸载成云端占位符（`ls -lO` 显示
> `dataless`），此后读写会报 `Resource deadlock avoided`，且磁盘满时 `brctl download`
> 也救不回来。本项目放在 `~/Developer/` 下就是为了避开这一点。
