# 日股 / 韩股 制度速查

> 用途：评估「给交易员加日股、韩股」需要动哪些规则。
> 资料截至 **2026-10-06**，来源见文末。**税率与假日表会变，改动前请复核。**

## 一句话结论

**技术上能接，但比港股麻烦**：港股有恒生指数日线可以直接当交易日历，
日韩没有可用的指数源，日历得自己维护；而且腾讯给日韩的字段语义与 A 股不同。

---

## 一、制度对照（A 股 / 港股 / 日股 / 韩股）

| | A 股 | 港股 | 日股 | 韩股 |
|---|---|---|---|---|
| **交易时段（北京时间）** | 09:30–11:30 / 13:00–15:00 | 09:30–12:00 / 13:00–16:00 | 08:00–10:30 / 11:30–14:30 | 08:00–14:30（**无午休**） |
| **当地时间** | 同北京 | 同北京 | 09:00–11:30 / 12:30–15:30 JST | 09:00–15:30 KST |
| **当日回转** | ❌ T+1 | ✅ T+0 | ✅ T+0 | ✅ T+0 |
| **交割** | T+1 | T+2 | T+2 | T+2 |
| **涨跌幅** | ±10%（ST ±5%） | 无 | **绝对金额分档**（非百分比） | ±30% |
| **最小单位** | 100 股 | 按手（每只不同） | 100 股 | **1 股** |
| **卖出税费** | 印花税 0.05% | 印花税 0.1% + 交易费 | **0** | **0.20%**（2026-01-01 起） |
| **佣金量级** | 万 2.5 | 0.25% 最低 HK$100 | ≈0（网络券商） | 0.015%（网络）～0.15% |
| **货币** | CNY | HKD | JPY | KRW |

**三个最容易搞错的点**：

1. **日韩都是 T+0（可当日买卖），T+2 只是交割**。把 T+2 实现成「T+2 才能卖」是
   常见且会显著改变手感的错误 —— 实测券商 FAQ 明确支持当日回转。
2. **韩股卖出税 0.20%**，比 A 股印花税高 4 倍，涨 1% 才勉强覆盖税+佣金。
   2026-01-01 刚从 0.15% 上调，**必须按日期分版本**（`rules.ts` 已经是按日期取规则的）。
3. **日股涨跌幅是绝对金额、不是百分比**，按前收分 35 档（100 日元以下 ±30 日元、
   5 万日元档 ±7000 日元……）。档位表可按分段线性近似，但**「绝对金额」这个语义不能丢**。

## 二、行情源实测（2026-10-06）

### 腾讯 `qt.gtimg.cn` —— 支持日韩个股，**不支持日韩指数**

| | A 股 | 港股 | 美股 | 日股 | 韩股 |
|---|---|---|---|---|---|
| 代码 | `sh600519` | `hk00700` | `usAAPL` | `jp7203` | `kr005930` |
| 字段数 | 88 | 78 | 73 | **72** | **72** |
| `[0]` | `1` | `116` | `delay` | `351` | `352` |
| **`[3]`** | **现价** | **现价** | **现价** | **现价** ✅ | **现价** ✅ |
| `[4]` / `[5]` | 昨收 / 今开 | 昨收 / 今开 | — | 昨收 / 今开 | 昨收 / 今开 |
| `[37]` 成交额 | 有（万元） | 有（元） | — | **空** ⚠️ | **空** ⚠️ |
| 币种标识 | `[82]` `CNY` | `[75]` `HKD` | `[35]` `USD` | **空** ⚠️ | **空** ⚠️ |
| 时间戳格式 | `20260930161454` | `2026/10/06 16:08:08` | `2026-10-06 14:30:00` | 同美 | 同美 |

✅ **日韩的 `[3]` 就是现价，与 A 股同口径**（`FIELD.price = 3` 可直接用）。
之前这里写过「`[3]` 是昨收、`[5]` 才是现价」，**2026-10-06 复核实测推翻了这个结论**。
自证方法：涨跌字段必须自洽 —— `[3] - [4]` 要等于 `[31]`、再除以 `[4]` 要等于 `[32]`：

```
jp7203  [3]=2930.5 [4]=2893.5 [31]=37      [32]=1.27873   2930.5-2893.5 = 37 ✅  37/2893.5 = 1.27873% ✅
kr005930[3]=272000 [4]=276000 [31]=-4000   [32]=-1.44928  272000-276000 = -4000 ✅  -4000/276000 = -1.44928% ✅
```

另一个交叉验证：日韩的 `[5]`/`[33]`/`[34]`（今开/最高/最低）与 Naver 的官方日线**完全一致**
（丰田 `open=2920 / high=2937.5 / low=2904`）。

⚠️ **日韩没有成交额**（`[37]`–`[44]` 全空）→ 界面上的成交额只能退回「价 × 量」估算。
`tencent.ts` 的 `amountOf` 对空值返回 `null`，调用方本来就要处理这种情况。

⚠️ **日韩没有币种标识**（`[75]`/`[82]` 为空）→ 币种只能从代码后缀推（`codes.ts` 的 `currencyOf`）。

⚠️ **不支持日韩指数**：`jpN225` / `jpTOPIX` / `krKS11` / `krKOSPI` / `krKOSDAQ`
全部返回 `v_pv_none_match="1"`。该接口支持的指数只有 `usDJI` / `usINX` / `usIXIC` /
`sh000001` / `sz399001` / `sz399006` / `hkHSI`。

⚠️ **搜索框不含日韩股**：`smartbox.gtimg.cn/s3/?q=toyota` 只返美股 ADR，
`q=samsung` 只返港股。标的池必须写死。

### 时间戳时区 —— **口径不统一，用前必须实测**

腾讯这一套接口**不同市场的时区口径不一样**，不能一刀切：

- **日韩给的是北京时间**：`jp7203` / `kr005930` 的 `[30]` 都是 `2026-10-06 14:30:00`。
  东京/首尔 15:30 收盘 = 北京时间 **14:30**；**若按当地时间应显示 15:30**。
  自证方法：在东京早已收盘的时刻（例如北京时间 19:00 之后）去拉，
  快照仍停在 `14:30` —— 那就是收盘时刻的北京时间。
- **美股给的是交易所当地时间**：`usAAPL` 的 `[30]` 是 `2026-10-05 16:00:02`，
  正是美东 16:00 收盘（若为北京时间应是次日 04:00）。

日韩均无夏令时，不存在美股那种季节性偏移；**只有美股这一条要在意时区**。
我们目前只把时间戳用于界面显示「更新于」，不参与「是否已收盘」的判断
（那个判断走 `session.ts`，本来就是北京时间），所以这个差异暂时不影响正确性。

## 三、要做的话，改动面

**必须进规则引擎的**（会改变玩家实际盈亏）：
1. 韩股卖出税 0.20%（按日期分版本）、日股 0 税
2. T+0（当日可卖）
3. 韩股 ±30% 涨跌停、日股绝对金额档位
4. 汇率损益：USD/JPY 过去一年 141–158（±12%）、USD/KRW 1338–1490（±11%），
   人民币记账下持仓会额外漂移 10%+ 量级
5. **交易日历按市场独立维护**：日本 1/1–1/3 + 12/31 休市，韩国 12/31 休市且
   **最后交易日是 12/30**。沿用 A 股日历会在 12/31 给出一个不存在的交易日。
6. 最小单位：日股 100 股（高价股一手 50 万日元，资金不足是真的买不起）、韩股 1 股

**可以简化的**：集合竞价/盘后市场/NXT 等时段细节、日股 35 档表用分段线性近似、
连续涨跌停扩幅规则、年度损益课税、指数编制方法学。

**没有现成数据、必须自建的两样**：
- **交易日历**：见下面的「历史日线源」—— 用同一市场若干只不会停牌的大盘股的日线日期**并集**反推
  （与港股拿 `hkHSI` 反推同一思路）。取并集是为了抗单只停牌：一只停牌只会多出一天，不会少一天。
  代价是**停牌与假日无法区分**，但几只超大市值股同日停牌的概率可以忽略。
- **涨跌停价**（东财对日韩股的 `f48`/`f51`/`f52` 全返回 `"-"`）。

### 历史日线源：Naver（**这是唯一实测可用的**）

日韩的日线**腾讯根本不提供**（`kline/kline?param=jp7203day,,,60` 只返 1 根，
`fqkline/get` 直接 501），东财 `push2*` 在本机被 IP 拦（见下），
**实测可用的是 Naver**，日韩走两个不同的接口：

| | 日股 | 韩股 |
|---|---|---|
| 接口 | `api.stock.naver.com/chart/foreign/item/{code}.T/day` | `api.finance.naver.com/siseJson.naver` |
| 参数 | `?startDateTime=YYYYMMDD000000&endDateTime=YYYYMMDD235959` | `?symbol={code}&requestType=1&startTime=YYYYMMDD&endTime=YYYYMMDD&timeframe=day` |
| 格式 | **标准 JSON** | **JS 数组字面量**（单引号，不是 JSON，要用 `ast.literal_eval`） |
| 字段 | `localDate` / `openPrice` / `highPrice` / `lowPrice` / `closePrice` / `accumulatedTradingVolume` | 表头 `['날짜','시가','고가','저가','종가','거래량','외국인소진율']` = 日期/开/高/低/收/量/外资持股比 |
| 需要 Referer | `https://m.stock.naver.com/` | `https://finance.naver.com/` |

- `{code}.T` 的 `.T` 是东京后缀；**韩股不能套用 foreign 接口**（`005930.KS` 返回 0 条），必须用国内接口。
- 实测深度：2026-05-01 → 2026-10-06 拿到 **日股 105 根 / 韩股 104 根**，
  足够 `DAYS = 130` 的窗口（约 6.5 个月）。
- **日韩指数都拿不到**（`KOSPI` / `KS11` / `N225` / `NI225` 在 foreign 接口返回 0 条），
  所以日历只能从个股反推。
- 交叉验证：Naver 的官方收盘与腾讯的 `[3]` 一致到小数点后一位
  （丰田两边都是 `2930.5`，三星腾讯 `272000` vs Naver `273000`，
  后者是收盘集合竞价的官方价，OHLC 其余三项完全相同）。

### 汇率：中行都能出，**韩元叫「韩国元」**

`fetch_snapshot.py` 已有的 `fetch_boc_fx(name_cn, pair)` 原样可用，只是名字要写对：

```python
fetch_boc_fx("日元",   "JPYCNY")   # 2026-10-06 = 4.2727 / 100 → 0.042727
fetch_boc_fx("韩国元", "KRWCNY")   # 2026-10-06 = 0.4958 / 100 → 0.004958
```

⚠️ **`currency_boc_sina(symbol="韩元")` 会 `KeyError`** —— 中行的名字是 **「韩国元」**，
不是「韩元」，也不是「韩币」。这一条踩过一次，别再踩。

（ECB 的 `api.frankfurter.dev/v1/latest?from=KRW&to=CNY` 也可用，实测 0.00499，与中行相差 0.6%，
但**必须加 `-L`** 跟 301 跳转。既然中行能出，就不引第二套口径了。）

### 已排除的源：东方财富 `push2*`（本机被 IP 拦）

- secid 前缀：日股 `176.`（`176.7203` = 丰田）、韩股 `177.`（`177.005930` = 三星电子）
  —— 前缀本身是**确认过**的：`searchapi.eastmoney.com` 的检索接口返回 `MktNum=176` / `177`，
  而检索接口在本机**可用**（只有 `push2*` 被拦）。
- ❌ **`push2.eastmoney.com` / `push2his.eastmoney.com` 在本机全部 HTTP 000**
  （TCP 连上后被服务端主动断开，`RemoteDisconnected`），
  **带不带 `Referer: https://quote.eastmoney.com/` 都一样** ——
  本文档早先写过「必须带 Referer 否则空响应」，那是**别的原因**，不是本机这个现象的解。
  编号主机（`1.`/`2.`/`7.`/`82.push2his`）与纯 IP 直连同样 000。
- 因此：**日韩的快照数据在本机生成不了**，只能靠 CI（不同出口 IP）跑。
  好在 `fetch_snapshot.py` 对港股汇率已经建立了「取不到就 warn + 跳过」的模式，
  日韩沿用同一个模式即可，不会影响 A 股与港股那部分。
- 字段（**未在本机验证**，来自公开资料，CI 上用到时要复核）：`f43` 现价 / `f46` 今开 /
  `f60` 昨收 / `f169` 涨跌额 / `f170` 涨跌幅（÷100）；⚠️ 日股 `f43` 有 ×10 缩放。
- 检索层有 `100.KS11`（韩国 KOSPI）与 `100.KOSPI200`，**但行情请求返回空，未验证可用**。
