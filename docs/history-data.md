# 历史数据：把玩家放回 2016–2024

传奇模式（模式 2）的十个关卡跑在过去，而每日快照只覆盖最近 120 个交易日。
这份文档说明那批深历史行情是怎么来的、经过哪些实测取舍、以及怎么重新生成。

## 一、为什么不能用每日快照

每日快照来自腾讯行情，**日线上限 641 根**（实测）。641 个交易日大约两年半，
够不到 2016 年。所以历史关卡另建一条数据管线。

## 二、数据源：新浪（akshare `stock_zh_a_daily`）

| 项目 | 实测结果 |
| --- | --- |
| 接口 | `ak.stock_zh_a_daily(symbol="sh600519", start_date, end_date, adjust="qfq")` |
| 最早可到 | 2001 年 8 月 |
| 单次耗时 | 跨 2016-01→2025-03（2244 行）约 **4.3–5.0 秒**；短区间（302 行）约 6.2 秒 |
| 返回列 | `date, open, high, low, close, volume, amount, outstanding_share, turnover` |
| 指数 | `ak.stock_zh_index_daily(symbol="sh000300")`，**只给 OHLC，没有 volume** |
| 代码映射 | `600519.SH` → `sh600519`、`000001.SZ` → `sz000001` |
| 北交所 | **不支持**（`.BJ` 一律跳过） |

区间越长单位成本越低，所以**一次抓一整段**（`2016-01-01 → 2025-03-31`）给十关共用，
不为每关重复请求。619 只在 `--workers 5` 下约 **12 分钟**。

### 为什么用前复权（qfq）

前复权用**今天的**复权因子回算，所以 2016 年的绝对价位和当年盘面不一样（被后来的分红除权压低了）。
好处是收益连续：长期持有不会因为除权缺口被算成暴跌。

模拟游戏比的是收益率，连续性比绝对价位重要得多，所以选 qfq，
并在关卡页面上明说「和当年的盘面绝对价位不一样」。

## 三、数据正确性验证

沪深300/上证指数不涉及复权，收盘点位可以直接和公开的历史事实对照：

| 日期 | 上证指数收盘（抓取） | 公开数值 | 当日涨跌 |
| --- | --- | --- | --- |
| 2020-02-03 | 2746.61 | 2746.61 | −7.72% |
| 2019-02-25 | 2961.28 | 2961.28 | +5.60% |
| 2024-09-24 | 2863.13 | 2863.13 | +4.15% |
| 2022-04-25 | 2928.51 | 2928.51 | −5.13% |

四个点位**逐一对上**，说明这批数据不是错位的、也没有缺日。

## 四、脚本

### `packages/data/scripts/fetch_history.py`

抓深历史到 `data/history-cache/<code>.json`（**不进仓库**，几十兆的中间产物）。

```bash
python3 -u packages/data/scripts/fetch_history.py --workers 5   # 全量，约 12 分钟
python3 -u packages/data/scripts/fetch_history.py --indices-only --fresh
```

| 参数 | 说明 |
| --- | --- |
| `--snapshot` | 用哪份快照的股票池，默认取 `data/` 下最新的 |
| `--from` / `--to` | 区间，默认 `2016-01-01` → `2025-03-31` |
| `--workers` | 并发数，默认 4。**并发太高会被新浪限流** |
| `--limit` | 只抓前 N 只，用于试跑。注意 `--limit 0` 等于**不限量** |
| `--fresh` | 忽略缓存重抓 |
| `--indices-only` | 只抓三个基准指数，不碰股票 |

**按股票缓存**：已存在的直接跳过。所以抓到一半断了、或者有几十只失败，
**直接重跑一次就行**——它只会补缺的那些，不会重抓 600 只。

失败率 > 5% 会中止（沿用 `fetch_snapshot.py` 的教训：脚本报「成功」而数据缺了一大块，
比直接失败更危险）。「当时还没上市」返回空数据，记入 `无数据`，不算失败。

### `scripts/build-history-shards.ts`

把缓存切成 `data/history/level-<id>.json`（**进仓库**，十关合计约 1.3 MB）。

```bash
npx vite-node scripts/build-history-shards.ts
npx vite-node scripts/build-history-shards.ts --per-level 80
npx vite-node scripts/build-history-shards.ts --level 2020-02-03
```

- 主日历取沪深300 的 2244 个交易日。
- 股票入选门槛：窗口内 **≥90% 的交易日有收盘价**，否则视为当时还没上市或长期停牌。
- **选股按窗口内的日均成交额（收盘价 × 成交量）从大到小取前 150 只。**
  用成交额而不是市值/权重，是因为「当时成交最活跃的那批股票」可以从数据算出来，
  而**历史权重拿不到 —— 拿今天的权重去排 2016 年的股票池才是真的错**。
- 每一列都严格与 `calendar` 等长（引擎按长度对齐，长度不一致会被当成「没有开盘价」）。
- 同时写一份 `data/history/index.json` 清单，网页用它判断站点发布了哪几关。

### 部署

`packages/data/scripts/sync_web_data.mjs` 在同步快照之后把 `data/history/*.json`
复制到 `apps/web/public/history/`，随站点一起发布。

## 五、已知限制

1. **ST 状态用的是今天的标记。** 历史 ST 状态拿不到，所以某只票在 2016 年是 ST
   （涨跌停 ±5%）而今天不是的话，这一关会按 ±10% 撮合。会影响极端行情下的一字板判定。
2. **前复权价位不等于当年盘面。** 见上。
3. **股票池是「成交额前 150」，不是当年的指数成分股。** 所以基准（沪深300）
   和股票池不是同一批标的 —— 这是有意的，玩家本来就可以买池子里的任何一只。
4. **北交所标的完全没有。** 新浪这个接口不支持，十关窗口里也没有北交所股票上市。
5. **停牌日表现为 `null`。** 引擎遇到没有开盘价的标的不猜价格，直接作废那笔委托并说明原因。
