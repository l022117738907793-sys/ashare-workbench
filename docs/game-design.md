# 模拟投资游戏板块 · 设计

> 状态：设计稿。等核心站点稳定后实施。
> 用户已明确「游戏板块体量挺大」，因此先定清边界再动手。

## 一、为什么这个游戏和「分析红线」不冲突

本项目有一条硬红线：**界面不出现买入/卖出/目标价**。而一个投资游戏天然涉及买卖。
两者并不矛盾，关键是分清「谁在决策」：

| | 谁做判断 | 是否合规 |
|---|---|---|
| 分析引擎 | **程序**给结论 | ❌ 越界——所以红线禁止 |
| 模拟盘 | **玩家**自己下单 | ✅ 程序只负责撮合与记账，不提供建议 |

所以模拟盘的定位是**玩家的决策沙盒**，而不是"AI 荐股"。程序永远不告诉玩家买什么，
只提供：真实行情、引擎的客观分类（带依据）、玩家自己的操作记录、以及事后复盘。

这与项目已有的「学习模式」「我为什么看好复盘」是同一脉络的延伸：
**看完分析 → 自己判断 → 下模拟单 → 事后对照数据复盘。**

## 二、合规与安全边界（必须守住）

1. **纯虚拟**，无任何充值、支付、提现入口，不与真实资金发生任何关联；
2. 显著位置常驻「模拟盘 · 虚拟资金 · 不构成投资建议」标识；
3. 不设"跟单"「荐股」「收益承诺」类功能与文案；
4. 不接入任何实盘交易接口；
5. 排行榜只展示模拟收益，不展示真实身份信息（默认昵称化）。

## 三、核心玩法（建议）

### 3.1 虚拟账户
- 初始虚拟资金 ¥1,000,000，可配置
- 持仓、可用资金、总资产、收益率
- 所有数据存 `localStorage`（纯前端，无后端）

### 3.2 撮合规则（关键：必须诚实）
用真实行情价撮合，但要明确处理前端做不到的部分：

| 项 | 处理方式 |
|---|---|
| 成交价 | 实时价（交易时段）/ 最新收盘价（非交易时段，并标注） |
| 非交易时段下单 | 允许，但**排队到下一交易日按开盘价成交**，并在 UI 标明 |
| 滑点 | 可配置（默认 0.1%），模拟真实冲击成本 |
| 手续费 | 万分之 2.5 + 印花税千分之 1（卖出），贴合 A 股实际 |
| T+1 | **必须实现**——当日买入不可卖出，这是 A 股基本规则，也是教学点 |
| 涨跌停 | 涨停不可买入、跌停不可卖出（按 ±10%/±20% 判断，ST ±5%） |
| 停牌/无行情 | 拒绝下单并说明原因，**不猜价格** |

> 这些规则本身就是很好的教学材料——比"能买卖"更有价值。

### 3.3 对局与结算
- **赛季制**：如一个自然月，到期按收益率排名
- 基准：沪深300 同期收益，**跑赢基准**才算有效成绩（避免"牛市人人都是股神"）
- 指标：总收益、最大回撤、胜率、交易次数、跑赢基准幅度
- 排行榜：本地（同学各自看）+ 可选导出 JSON 汇总到仓库静态文件

### 3.4 与既有功能联动（这是本项目的独特性）
- 下单时若该股当前分类是「高位观察」，弹提示但**不阻止**（让玩家自己做决定）
- 每笔交易自动记入「复盘」：当时的引擎分类 + 判断依据快照
- 结算时生成复盘报告：**哪些交易与分析结论一致、哪些相悖、结果如何**

  > 这让游戏从"赌大小"变成"检验自己的判断力"，也呼应原项目的学习定位。

## 四、技术方案

复用现有架构，不引入新依赖：

```
packages/game/          ← 新包：纯函数、零依赖、可单测
  src/portfolio.ts      持仓与资金（买入/卖出/T+1/手续费）
  src/matching.ts       撮合规则（涨跌停/滑点/非交易时段排队）
  src/settlement.ts     结算与绩效指标（收益率/回撤/胜率/跑赢基准）
  src/types.ts
apps/web/src/views/
  GameView.tsx          账户总览 + 下单 + 持仓
  LeaderboardView.tsx   排行榜
```

要点：
- **纯函数**，与 `@aw/core` 同样的风格，全部可单测；撮合逻辑是重点测试对象
- 数据全部 `localStorage`，无后端、无账号体系
- 撮合输入是 `Quote`（`@aw/data` 已提供），天然复用实时层
- 排行榜靠**静态 JSON + GitHub PR**（同学把自己的成绩导出提交），不做后端

## 五、工作量拆解与顺序

| 阶段 | 内容 | 预估 |
|---|---|---|
| 1 | `packages/game` 账户与撮合 + 单测（T+1/涨跌停/手续费/滑点） | 中 |
| 2 | 下单与持仓 UI，接入实时价 | 中 |
| 3 | 结算与绩效指标（收益/回撤/胜率/基准对比） | 小 |
| 4 | 复盘联动（把交易记录接进既有复盘模块） | 中 |
| 5 | 排行榜（静态 JSON 方案） | 小 |

**建议先做 1、2、3**：有了账户、撮合和结算，游戏就成立了；4、5 是增强。

## 六、明确不做（避免范围失控）

- 不做真实资金、不做账号注册、不做后端、不做实时多人对战
- 不做融资融券、期权、期货等衍生品
- 不做「AI 帮你交易」——那会直接违反本项目的分析红线
