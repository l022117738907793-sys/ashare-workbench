# 术语高亮与交易员问答

> 面向第一次接触股票的人：**凡是看不懂的词，点一下就有解释。**
> 解释分两层，都是写好的；AI 问答是可选的，没配就整块不出现。

## 一、为什么要做

这个站点的功能是「用真实数据做分析演练」，但它默认读者知道「均线」「回撤」
「T+1」「一手」是什么意思。对没接触过股票的学生，一屏里可能有十几个生词 ——
每次都要去搜索，学习成本直接压过了内容本身。

所以做了这一层：**界面里出现的专业词一律标蓝，点开就地解释，不跳走**。

## 二、两层解释，点两下

| 动作 | 出现什么 |
|---|---|
| 点第一下 | 就地撑开一小条：**一句话**说清这个词 |
| 点「让交易员细讲」 | 展开完整解释（几段话，讲清「是什么 / 为什么重要」） |
| 点「问交易员」（可选） | 一个输入框，问这个词相关的问题 |

**为什么不做浮层（tooltip）。** 浮层会盖住下面的内容 —— 而这个页面下面常常就是
下单按钮。用 `display:block` 的 `<span>` 把解释**撑开在原地**，读完之后继续往下滚，
不会遮住任何东西。

**为什么点两下。** 一屏十几个词，全给完整解释会变成一屏解释。第一下只给一句，
确认「这就是我要找的词」之后再看长的。这是用户定的交互。

**同时只展开一个词。** 用模块级的单值订阅（`hisui.ts` 里的
`subscribeHisui` / `getOpenRef` / `setOpenRef`）而不是把状态从 `App` 一路透传下来 ——
一个页面上有几十个术语位置，逐层传 prop 会把每条链路都污染。

## 三、词典

`apps/web/src/lib/glossary.ts`，44 条。每条形如：

```ts
{ id: "滑点", short: "按下单时的参考价成交，通常会差一点点。", full: "……**下一交易日的开盘价**……" }
```

- `short` 是一句话，出现在气泡里，也是按钮的 `title`（鼠标悬停也能看到）；
- `full` 可以写 `**强调**`，渲染时变成 `<strong>`（`Terms.tsx` 的 `rich()`，
  不然星号会原样显示给玩家）；
- `alias` 用于同义写法（`昨收价` → `昨收`）。

匹配规则在 `findTerms`：**按匹配文本长度降序试，同一位置只取最长的那个**，
再用 `taken` 区间去重。所以「可卖数量」不会被切成「可卖」+「数量」。

**词典里的数字都对着 `packages/game/src/rules.ts` 核过**：
佣金 0.00025（最低 5 元，双向）、印花税 0.001 → 0.0005（2023-08-28 起，仅卖出）、
过户费 0.00001（双向）、滑点 0.001、一手 100 股（科创板 200 股起、之后 1 股递增）。
「手续费是万分之二点五」这种话写错了，比不写还糟。

## 四、覆盖到哪儿

`common.tsx` 里有三个层次的接入：

1. `asTerms(node)` —— 字符串才过一遍。用在 **Card 的 title/subtitle、KV 的键、
   ReasonList 的 label/note、Notice、EmptyHint**。玩家最先读到的就是这些位置，
   这一层做掉等于覆盖了大部分界面；
2. `asTermsDeep(node)` —— 递归进 JSX，把每个**纯文本片段**都换掉，带结构的标签
   （`<strong>`）原样保留。用在正文段落上；
3. `<RichP>` —— `asTermsDeep` 的 `<p>` 包装。`GameRulesView` / `GuideView` /
   `GameView` / `ReplayView` / `LevelPicker` 里的 `rule-body`、`hint` 段落用它。

**一条硬约束**：术语渲染出来是 `<button>`。若这段文字的祖先里有 `<button>` 或
`<a>`，就会变成非法的嵌套可交互元素，浏览器会把结构拆开 —— 表现是「点了没反应」。
所以 `asTermsDeep` **只能用在纯展示的段落上**。`views.test.ts` 里有一条
`nestedButtonsIn` 守着规则页与使用说明页。

## 五、交易员

界面上的显示名是 **交易员**（`HISUI_NAME`）。角色素材来自琥珀做的接入包
（`翡翠教学助手-DeepSeek接入包.zip`），原出处是《月姬》的翡翠：
自称「交易员」、用「您」称呼玩家、短句、克制，不因为虚拟盈利夸人、也不因为亏损责备。

**内部标识仍叫 `hisui`**：`hisui.ts`、`HISUI_NAME`、`HisuiMood`、存档键
`aw.hisui.v1`、`hisui-expressions.webp` 全都没改名 —— 存档键一改，
用户填过的代理地址就丢了。显示名与内部名不一致这件事写在这里，
免得下次有人当成漏改。

素材是接入包里的表情精灵图，用 `cwebp -q 82 -alpha_q 90` 从 1536×1024 压到
**576×384**（每格 192×192），2.2 MB → 58 KB。取格方式是
`background-size: 300% 200%` + `backgroundPosition: ${col*50}% ${row*100}%`。

图要 **import 进来**（`import hisuiSheet from "../assets/hisui-expressions.webp"`），
不能写死 `/hisui/...` —— vite 的 `base` 是 `"./"`，写死会在 GitHub Pages 子路径下 404。

## 六、AI 问答：可选，且有硬边界

**这个站点是纯静态的，没有后端，不能保管任何密钥。** 接入包自己的 README 也这么写：
「纯静态页面不能保管服务端密钥」「不要把密钥写入前端、JSON 台词文件或 Git 仓库」。

所以 AI 那部分是这样落的：

- **默认整块不出现。** `AskBox` 在 `isUsableEndpoint(endpoint)` 不通过时直接
  `return null` —— 绝不能有「看着能问、点了说没接通」的假入口；
- 地址只在**设置页填**（`aw.hisui.v1`），或构建期给 `VITE_HISUI_ENDPOINT`；
  密钥放在**使用者自己的代理**上，不进这个仓库；
- 只接受 `https://` 开头的完整地址；
- **请求体只有三个键**：`term` / `context` / `question`。`context` 是那条已经写好的
  词典释义。不发送账户、持仓、日期、行情 —— 接入包 §5 要求按 runId 裁剪上下文、
  过滤未来信息，那需要服务端重建「此刻可见的事实」，本仓没有后端，
  **于是宁可不发**：不发送的东西不会泄露。这条有测试钉着
  （`hisui.test.ts` 断言请求体的 `Object.keys` 恰好是那三个）。

## 七、测试

- `apps/web/src/lib/glossary.test.ts` —— 找词、重叠取长、别名、词典自身的规矩；
- `apps/web/src/lib/hisui.test.ts` —— 地址判断、存档解析、订阅、**请求体形状**；
- `apps/web/src/terms.test.ts` —— 切分渲染、`rich()`、无嵌套按钮、DayNewsCard；
- `apps/web/src/views.test.ts` —— 加了 `plain(html)` 助手（去掉标签只留文字）。
  **术语会把连续短语切开**（`<h2><button>板块</button><span>强弱</span></h2>`），
  对 HTML 直接 `toContain` 会误报成「文案丢了」；
  断言**用户读到什么**时用 `plain()`，断言**结构**（class / aria / 顺序）时仍看原始 HTML。
