# 交易员 AI 配置：照着做即可接入现有页面

本版已准备好前端问答入口、服务端代理、Cloudflare Workers 部署文件和模拟测试。**目前没有填真实密钥，没有部署代理，也没有执行真实收费请求。**先完成下面的代理部署，再在网页里填写代理地址，才算真正接通。

界面显示名是「交易员」，代码、素材名与部署名仍叫 `hisui`（素材原本是《月姬》的翡翠）。**两者不一致是有意的**，理由见 `docs/terms-and-hisui.md` 第五节。本文说的就是页面里这位助手。

## 1. 要准备什么

- 一个可以登录的 [DeepSeek 开放平台账户](https://platform.deepseek.com/)，在平台的 API Keys 页面创建服务端密钥，并确认账户可以调用 API。网页版聊天的登录或会员不等于 API 已配置。
- 一个 [Cloudflare 账户](https://dash.cloudflare.com/)。下面采用 Workers 托管代理，它会提供 HTTPS `workers.dev` 地址；前端仍放在现有 GitHub Pages。
- 电脑上安装 Node.js 22 或更高版本。资源包自带代理项目，不必另建框架。

接入路线：玩家提问 → 网页问答代理地址 → Cloudflare Worker → DeepSeek → 回答文字和表情。供应商密钥只保存在 Worker 的 Secret 里；网页只保存公开的代理网址。

## 2. 找到代理文件并检查本地代码

解压资源包后，在其中的 `source/reference/hisui-ai-proxy/` 目录打开终端。不要在项目根目录执行下列 `npm ci`，这是独立的代理子项目。

```sh
npm ci
npm test
npm run check
```

`npm test` 用假的上游返回验证问答、来源限制、限流和每日额度，**不会调用 DeepSeek**。`npm run check` 是 Wrangler 的打包检查，带 `--dry-run`，**不会发布**。本包已经通过这两项验证。

文件分工：

| 文件 | 用途 |
| --- | --- |
| `wrangler.jsonc` | Worker 名称、模型、允许来源、开关、限流与持久预算配置 |
| `worker-entry.mjs` | Workers 入口和每日额度对象 |
| `worker.mjs` | HTTPS 接口、CORS、输入检查、限流和预算逻辑 |
| `proxy.mjs` | DeepSeek 请求及回答格式处理 |
| `knowledge.json` | 从当前应用词典导出的服务器规则，不含行情和存档 |
| `server.mjs` | 保留的 Node 服务方案；选 Workers 时不必启动它 |

## 3. 在配置文件里确认三个值

打开 `wrangler.jsonc`：

1. `name` 默认 `ashare-hisui-teacher`，可以保持；如果该账户已有同名 Worker，可改成自己的名字，例如 `ashare-hisui-teacher-demo`。
2. `ALLOWED_ORIGINS` 默认已填网站与当前本地预览的来源：

```text
https://ashare-workbench.pages.dev,https://l022117738907793-sys.github.io,http://localhost:5192,http://127.0.0.1:5192
```

第一个是现在的主站（Cloudflare Pages）；GitHub Pages 那个旧地址保留着，**两边都要列** —— 少写一个，从那个域名打开的页面就会被代理 403。

来源只能写“协议 + 域名 + 端口”，**不能加 `/ashare-workbench/`、`/device-preview.html` 或末尾 `/`**。本地预览换端口时，把实际端口添加进去；测试结束可删掉两个 localhost 来源，只保留正式网站。

3. `HISUI_MODEL` 默认 `deepseek-flash`。这是 2026-10-10 从 [DeepSeek 官方快速开始](https://api-docs.deepseek.com/quick_start)核对的模型名称；以后供应商改名，只改服务端配置再部署。密钥不写在这个文件里。

本版其他设置已提供默认值：

| 字段 | 默认值与作用 |
| --- | --- |
| `DAILY_REQUEST_LIMIT` | `300`，整个 Worker 每个 UTC 日最多预留 300 次模型请求；北京时间每天 08:00 换日 |
| `ENABLED` | `true`；改为 `false` 并重新部署可暂停 AI，离线解释继续可用 |
| `HISUI_RATE_LIMITER.simple` | 同一来源 IP 每个 Cloudflare 地点每分钟约 6 次，用于小组演示的节流 |
| `namespace_id` | `61010`，限流命名空间；账户内其他应用已使用这个编号时换一个正整数字符串 |

每日预算使用一个固定名称的 Durable Object 持久保存，Worker 重启或重新发布不会清空当天计数；上游失败也消耗一次预留，避免失败重试无上限。每分钟限制按边缘地点运行，并非精确全球计费；真正的每天总额由持久预算限制。

## 4. 登录并发布代理

仍在代理目录执行：

```sh
npx wrangler login
npm run deploy
```

第一条会打开 Cloudflare 授权页面，登录自己的账户并授权。第二条会正式发布 Worker；首次使用若提示设置 `workers.dev` 子域名，按提示完成。终端会返回形如下面的地址：

```text
https://ashare-hisui-teacher.你的子域名.workers.dev
```

**以终端实际返回的网址为准。**把它记下来，稍后网页要填的是在这个网址后加 `/ask`。

先打开 `https://实际地址/health`。未配置密钥时应该看到：

```json
{"service":"hisui-teaching-proxy","configured":false,"enabled":true,"model":"deepseek-flash"}
```

这一步只检查服务在线，不会调用模型，也不消耗模型请求额度。登录、发布与自动提供 `workers.dev` 地址的流程依据 [Cloudflare 官方 CLI 入门](https://developers.cloudflare.com/workers/get-started/guide/)；登录命令可查 [Wrangler login](https://developers.cloudflare.com/workers/wrangler/commands/general/#login)。

## 5. 把 DeepSeek 密钥存为服务器 Secret

执行：

```sh
npx wrangler secret put DEEPSEEK_API_KEY
```

终端提示 `Enter a secret value` 后，粘贴自己刚创建的密钥并回车。**只在这个交互提示里填，不要把密钥写进命令、代码、截图或发给 DeepSeek。**命令完成后，Secret 会更新 Worker 并立即生效。

再打开 `/health`，`configured` 应变成 `true`。它只证明服务器存在密钥，不证明密钥有效或余额足够；下一步用真实提问验证。Secret 的交互式录入和立即发布行为已按 [Cloudflare 官方 secret put 文档](https://developers.cloudflare.com/workers/wrangler/commands/workers/#secret-put)核对。

## 6. 在模拟盘网页里填写地址

1. 打开现有模拟盘，点击页头右上角齿轮进入“设置”。
2. 找到 **“交易员的问答（可选）”**。
3. 在“问答代理地址”填：

```text
https://ashare-hisui-teacher.你的实际子域名.workers.dev/ask
```

4. 点“保存”。页面显示“已配置……（尚未验证连接）”是正常的，这只是保存网址。
5. 返回游戏或学习页面，点开一个带解释的术语，或展开助手的常见问题。配置了有效 HTTPS 地址后，会显示提问框。
6. 先问“挂单为什么没有马上成交？”或“T+1 是什么意思？”。出现回答、头像切换对应表情，才说明网页到模型的完整链路接通。**这一次会真实调用 API，可能产生费用。**

不用填写 DeepSeek 官方的 API 地址，也不用填写 API Key。页面输入框只接受自己的 **HTTPS 代理 `/ask` 地址**；`http://localhost:8787/ask` 不能作为现有前端的问答地址。

此处保存仅影响这台设备的这一个浏览器。手机要自己填一次，电脑另一个浏览器也要填一次；不必清空游戏存档。

## 7. 如果希望所有新用户默认能问

先确认代理已经通过真实问答，再由开发者给前端构建提供 `VITE_HISUI_ENDPOINT`。它是公开网址，**不是密钥**。

本仓库的 `.github/workflows/deploy-web.yml` 里，`Build web app` 步骤**已经配置好**（用的是 Pages 入口，原因见第 12 节）：

```yaml
- name: Build web app
  # 问答代理地址在构建期注入，线上所有访客默认就能用（公开网址，不是密钥）。
  # 用 pages.dev 那个入口而不是 workers.dev：后者在大陆被屏蔽。
  env:
    VITE_HISUI_ENDPOINT: https://ashare-hisui-proxy.pages.dev/ask
  run: npm run build --workspace @aw/web
```

换成自己的代理时改这一行即可，然后重新部署 GitHub Pages，新用户就会默认使用它。已有浏览器自己保存过的问答设置优先，若以前保存过空地址或旧地址，应在设置里手动填入新地址。不要为此清空本地数据。

打开公众默认问答前，除了本版来源限制、节流与每日预算，还应为正式服务加入用户身份验证或验证挑战。**Origin 只能限制普通浏览器跨站请求，不能证明调用者身份；当前协议没有用户登录验证。**小组演示可先保持低总额度；后续公开推广由 DeepSeek 在保持当前接口兼容的前提下补足验证机制。

## 8. 头像表情和人物怎么改

回答格式一直保持：

```json
{"mood":"explain","answer":"历史推演中的委托会在下一交易日开盘尝试撮合。"}
```

| `mood` | 对应表情 |
| --- | --- |
| `neutral` | 平常 |
| `thinking` | 思考；前端等待回答时使用 |
| `explain` | 讲解 |
| `concern` | 提醒注意 |
| `happy` | 鼓励 |
| `sorry` | 暂时答不上来 |

现有图片资源和前端 `MOOD_CELL` 已经支持这六种状态，代理返回 `mood` 就能切换，不需要为每个表情另接 API。它是表情切换与现有等待动画；如果要嘴型同步或连续动作，需要另外制作动画素材。

人格、口吻和问答范围在 `proxy.mjs` 的 `system` 文本中调整。建议维持：短句、温和、先解释概念，再说明游戏里怎么看。要改显示名，只动两处 —— `apps/web/src/lib/hisui.ts` 的 `HISUI_NAME`，与本文档同级的 `proxy.mjs` 里 `system` 提示中的那个名字 —— 再重建前端、重新部署代理；`hisui` 内部模块、素材名、`aw.hisui.v1` 存储键与 `ashare-hisui-*` 部署名都不用动。

## 9. 当前版本能回答什么

第一版回答应用规则、操作方法和词典内的股票术语。代理**忽略客户端传来的 `context`**，用服务器 `knowledge.json` 作为规则来源；词典变更时必须同步更新。请求最多 200 字，回答最多 600 字。

当前不上传账户、持仓、真实日期或行情，不能因此期待它判断某只股票当前该买还是卖。系统提示要求不推荐具体买卖、不预测价格、不猜关卡日期、不透露历史后续；提示词不能完全消除模型记忆中的历史知识，因此不要把自由历史新闻分析开放成通关捷径。

如果以后要让它讲解“我这一局为什么亏了”，应先由服务端建立局与进度记录，只把玩家当前阶段看得到的事实发给模型。不能把整个历史区间交给模型，再只靠一句“别剧透”。这一阶段不在当前资源包中实现。

## 10. 故障对照

| 现象 | 检查办法 |
| --- | --- |
| 保存了地址，却没看到提问框 | 地址是否 HTTPS、是否保存；返回后重新展开术语或常见问题；必要时刷新页面，不清存档 |
| `/health` 的 `configured` 为 false | Secret 是否叫 `DEEPSEEK_API_KEY`；录入时所在目录和 Worker 名称是否正确 |
| `/health` 为 true，提问仍失败 | 检查平台 API Key、余额/调用资格、模型名称；health 不验证这些 |
| HTTP 403 或浏览器跨域报错 | `ALLOWED_ORIGINS` 是否包含当前来源；检查协议、域名、端口，不含路径；改完要重新部署 |
| HTTP 404 | 网页填写地址是否以 `/ask` 结束 |
| HTTP 400 / 413 | 问题或请求格式过长；本版问题限 200 字，请简化 |
| HTTP 429 | 等一分钟再问；若当日总额耗尽，等北京时间次日 08:00 或调整服务器额度 |
| HTTP 503 | 密钥未配、服务已暂停或保护绑定未配置；先看 health，再核对完整 wrangler 配置 |
| HTTP 502 | 上游超时/报错/回复不满足 JSON 格式；稍后重试；代理不会把供应商密钥或错误原文送到网页 |
| 手机能进网页，代理域名打不开 | 若地址是 `*.workers.dev`，在中国大陆一定打不开（原因与做法见第 12 节），改成 Pages 入口地址即可；接口不变 |

直接在浏览器地址栏打开 `/ask` 会发送 GET，不是正确的问答测试；代理返回 403 或 405 并不等于部署失败。使用 `/health` 看存活，用网页提问验证实际回答。

## 11. 开发者验证记录与备用方案

本版使用 Wrangler 4.149.0，14 项代理模拟测试通过，Wrangler 打包检查通过，并以无密钥的本地 Worker 验证存活与跨域预检。**发布与真实模型调用随后也已完成验证**，见下面两节。代理运行代码零外部 SDK；Wrangler 只负责本地运行、打包和发布。Node 参考服务仍可用：

```sh
node server.mjs
```

Node 服务只监听 `127.0.0.1:8787`，公网要配 HTTPS 反向代理；它的内存每日预算和单进程限流不等同于 Workers 的持久预算，多实例请用共享存储。推荐按本文 Workers 路径完成第一版，而非同时启动两套。

限流绑定语法与“边缘地点限额、最终一致”的限制核对自 [Cloudflare Rate Limiting 官方文档](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)；持久预算类的注册、SQLite 存储与绑定核对自 [Durable Objects 官方入门](https://developers.cloudflare.com/durable-objects/get-started/)。模型接口为 `https://api.deepseek.com/chat/completions`，鉴权为服务器请求的 `Authorization: Bearer …`，依据 [DeepSeek 官方快速开始](https://api-docs.deepseek.com/quick_start)。

代理明确使用 `thinking: {type: "disabled"}` 和 `response_format: {type: "json_object"}`，并在提示词里给出 JSON 示例，适合短规则问答；官方说明见 [JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 与 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)。模型仍可能返回空内容或因长度截断，解析失败会显示重试提示，不伪造回答。

## 12. 中国大陆打不开 `workers.dev`：改用 Pages 入口转发

第 4 节发布出来的 `https://<名字>.<子域名>.workers.dev` **在中国大陆的网络里打不开**，而且不是「慢」或「偶尔失败」：

- 系统 DNS 把它解析成 `128.242.250.155` 这类地址（污染结果），连过去直接超时；
- 换成腾讯 DoH 查到真实 Cloudflare 地址后强制解析，TCP 是通的，但 **TLS 握手发完 ClientHello 就立刻被重置** —— 屏蔽发生在 SNI 层面；
- 同一个网络的 `www.cloudflare.com`、`api.cloudflare.com`、`dash.cloudflare.com` 都正常，**`pages.dev` 也正常**。

所以代理本体仍然部署成 Worker（规则、限流、每日额度、密钥全在它上面），另外在 **Cloudflare Pages** 上放一个只做转发的小入口。用户在网页里填的是 Pages 那个地址。

代理目录里的这两个脚本就是这件事：

```sh
cd reference/hisui-ai-proxy
npm run pages:build    # 拼出 pages/.pages-build/
npm run pages:deploy   # 发布到 Pages 项目 ashare-hisui-proxy
```

- `pages/_worker.js` 是入口本体：`/ask` 与 `/health` 原样转发给 Worker（连同 `Origin`、`CF-Connecting-IP` 与方法/请求体），其余路径交给同目录的静态文件。
- `pages/wrangler.jsonc` 只有项目名、输出目录和 `compatibility_date`；**变量与密钥都不在这里**，它们仍然属于 Worker。
- `pages/build.mjs` 把 `worker.mjs` / `proxy.mjs` / `knowledge.json` 复制进输出目录 —— 规则与提示词只有一份源文件，改完 `proxy.mjs` 重新 `pages:deploy` 就同步过去。

换自己的 Worker 时改 `pages/_worker.js` 顶部的 `UPSTREAM` 常量。

**Pages 上不能做的事**（试过会报错，别浪费时间）：Pages 的配置文件不支持 `migrations`，Durable Object 绑定必须写 `script_name` 指向另一个 Worker。所以限流与每日额度的两个绑定**没法搬到 Pages 项目上**，这正是选择「只转发」而不是「把规则搬到 Pages」的原因。
